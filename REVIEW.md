# REVIEW.md

Defects found in the starter `app/main.py`, and what I did about each. Every one is fixed in the new `app/main.py`.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Shift start is built with `punch_in.replace(hour=, minute=)`, i.e. in the punch's own time zone (UTC / server-local), not IST (R1). | Punch-in 10:05 IST = 04:35Z, shift 09:30: start becomes 09:30Z, delta is negative, so `late_minutes` is 0 instead of 35. | Shift start is built as an IST instant for the attendance date (`shift_window`). |
| 2 | `compute_late_minutes` | Grace check runs on the already floored minutes (`minutes > 10`). | 09:40:30 floors to 10, so it is not late; R2 says it is (10:30 > 10:00) and `late_minutes` should be 10. | Compare whole seconds: late only if `seconds > 600`, then `seconds // 60`. |
| 3 | `compute_late_minutes`, `compute_overtime` | No overnight shifts: the shift start / end are put on the punch's calendar day. No truncation to whole seconds. | 22:00-06:00 shift, punch-out 06:40 next day: "overtime" is computed against 06:00 on the wrong day. A 03:00 punch-in is measured against 22:00 of the *same* day. | `shift_window` puts the end of an overnight shift on the next day; `attendance_day` implements the R1 exception; instants are truncated to seconds. |
| 4 | `compute_work_hours` | Python `round()` is banker's rounding on a binary float (R4 wants half-up). | 29250 s = 8.125 h returns 8.12, expected 8.13. | Exact `Fraction(seconds, 3600)` rounded half-up (`round_half_up`). |
| 5 | `compute_overtime` | No 30-minute minimum (R3); ignores overnight; returns minutes for any positive gap. | Leaving 5 minutes after shift end returns 5, expected 0. | Floor to minutes, count only if >= 30. |
| 6 | `EmployeeIn` | No validation at all: `emp_code` format, e-mail, `HH:MM` shifts, lengths, `joined_on` real date, `shift_start != shift_end`. Garbage is stored and later breaks analytics. | `joined_on: "yesterday"` or `shift_start: "9:5"` returns 201. | Pydantic constraints (patterns use `[0-9]`, not `\d`) plus validators; invalid input gives 422. |
| 7 | `create_employee` | Check-then-insert, no unique index: two concurrent creates both succeed. | 20 parallel POSTs of one `emp_code` give several 201s. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. |
| 8 | `create_employee` | `created_at = datetime.now()` is naive local time that PyMongo stores as if UTC; the response returns a datetime (ISO string), not epoch ms. | `created_at` off by the server's UTC offset; wrong type in the response. | Aware UTC datetime at millisecond precision; returned as epoch ms. |
| 9 | `list_employees` | `skip = page * page_size` skips the first page; `total` counts the whole collection, not the filter; no sort; no bounds on `page` / `page_size`; `if department:` ignores `""`. | `page=1` returns the 2nd page; `?department=X` returns the wrong `total`; `page=0` gives a negative skip (500); `page_size=100000` accepted. | `skip = (page-1)*page_size`; `count_documents(filter)`; sort by `emp_code`; `page >= 1`, `1 <= page_size <= 100`. |
| 10 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises `TypeError`, giving a 500. | POST with an unknown `emp_code`. | 404. |
| 11 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` is naive and in server-local time, so `date` is the server's date, not the IST date (R1), no overnight rule, no truncation. `punched_at=0` is falsy and treated as "now". | Punch-in 00:30 IST on the 6th on a UTC server is stored on the 5th. | UTC-aware conversion, `attendance_day` (IST + overnight rule), whole seconds, explicit `is not None` check. |
| 12 | `PunchInIn` | `punched_at: Optional[int]` is lax: accepts `"1783312500000"`, `true`; a seconds value (1783312500) or a huge number is accepted or crashes with `OverflowError` (500). `status: str` accepts anything, including `ABSENT`. | Send a string / seconds / `"ABSENT"`. | Strict int with range 1e11..4.1e12 (422 otherwise); `status` is `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 13 | `punch_in` | Check-then-insert race and no unique index on (`emp_code`, `date`). | Two simultaneous punch-ins both return 201. | Unique (`emp_code`, `date`) index; `DuplicateKeyError` becomes 409. |
| 14 | `punch_in` | Response leaks the internal id (`id` = ObjectId string) and returns `punch_in` as an ISO datetime instead of epoch ms; `work_hours` etc. aren't normalised. | Compare the response with the `AttendanceRecord` schema. | `format_record` builds the contract shape; `_id` never leaves the database. |
| 15 | `list_attendance` | Loads the whole collection into memory, sorts and slices in Python: O(N) per request. Sort is by `date` only (no `emp_code` tie-break); no indexes. | 100k records: slow, large memory; ties come back in arbitrary order. | Sort / skip / limit in MongoDB, backed by `(date desc, emp_code)` indexes; `estimated_document_count()` when unfiltered. |
| 16 | `list_attendance` | `page=0` gives a negative slice and returns wrong data; unbounded `page_size`; `id` leaked; datetimes returned raw; legacy docs without `half_day` / `history` returned incomplete; `date_from > date_to` and unknown `status` not rejected. | `page=0`, `status=FOO`, `date_from=2026-08-01&date_to=2026-07-01`. | Validated params (422), `format_record` defaults legacy fields, `date_from > date_to` is 422. |
| 17 | `health` | Always returns ok without touching MongoDB. | Stop MongoDB: `/health` still says 200. | Pings MongoDB, 503 on failure; also retries index creation. |
| 18 | module setup | `MongoClient` without `tz_aware` returns naive datetimes; no server-selection timeout (a dead DB hangs a request for 30 s); no index creation at startup. | Naive datetimes in responses; hanging calls; every query is a COLLSCAN. | `tz_aware=True`, 5 s timeouts, idempotent index creation in the startup lifespan. |

## Examined and judged NOT a defect

* `load_dotenv()` with its default `override=False`: real environment variables already win, as the contract needs.
* `doc.pop("_id")` after `insert_one`: `insert_one` adds `_id` to the dict, and popping it does hide it. (The id leak in `punch_in` is a separate problem: #14.)
* Comparing `date` strings with `$gte` / `$lte`: `YYYY-MM-DD` sorts lexicographically in date order, so the string filter is correct.
* Plain `def` endpoints with a module-level `MongoClient`: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so parallel requests are fine.
* Defaulting `shift_start` / `shift_end` to 09:30 / 18:30 matches the contract.
* The helpers could not be reused as they were (items 1-5): I rewrote them as exact, IST-aware functions that the punch endpoints and the correction endpoint share.
